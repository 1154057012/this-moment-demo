# AI使用记录｜这一刻

日期：2026-10-28。本文记录实际协作；未完成项目明确标记，最终交付前更新。

## 工具与作用

- Codex：依据笔试题和用户选择，提出选题、用户故事、页面流程、功能取舍及实现方案；辅助编写产品说明、交互网页与验收材料。
- PDF工作流：使用ReportLab生成五页中文PDF，使用pypdf核对页数和文本，使用Poppler渲染全部五页图片并逐页检查布局。该流程属于代码辅助文档制作，不是AI模型能力。
- 素材加工：8段Pexels视频片段；原素材无声。后期加入CC0海浪实录与原创合成器配乐。完成30秒基础版、30秒突出海浪声版、24秒缩短版及24秒组合修改版。
- 本次Demo中的“AI生成”：规则与预制示例结果模拟，未接真实模型；与制作作业使用的Codex分开披露。

## 已发生的人工输入与决定

1. 提交者选择“日常、旅行或生活记录”作为熟悉的创作场景。
2. 提交者要求完整网页Demo、GitHub代码与网页链接，并确认开始制作。
3. 提交者将第5题的产品选择交给AI；这不等于已提供本人使用经历。
4. 海边一日游、20段视频和朋友笑声为设计场景，不作为本人经历或访谈事实。

## 已发生的方案调整

| 初始方案或风险 | 处理 | 判断原因 |
| --- | --- | --- |
| 泛化的一键旅行成片 | 聚焦“必留片段＋一句话意图” | 需要具体说明产品在用户表达上的价值 |
| 不满意就整条重新生成 | 改为海浪声、海景时长等局部修改，并支持撤销 | 保留满意内容，降低试错成本 |
| 自由输入可能被误认为真实AI理解 | 明确展示模拟范围和可用操作 | 让评审理解原型能力边界 |
| 第5题缺少真实经历 | 标为典型场景机制分析，个人经历待核实 | 不编造第一人称经历 |
| 产品成效缺少数据 | 写需求假设和验证计划 | 不把设计推断写成真实调研结论 |

## AI输出不符合预期的地方

- 先前方案过宽，容易把“AI剪片”写成已有功能的重复描述；已收窄到个人重要性与局部修正。
- 先前描述容易混合“实际可操作的Demo”与“真实模型理解”，现分别说明。
- 功能分析草稿如果写成第一人称会超出已知事实；最终稿明确标注个人经历缺口。
- 初版场景以“保留笑声”为例，但实际获取的示例视频无声。改为“突出海浪声”，公开说明海浪为后期加入的CC0录音，不能将其称为现场原音。
- PDF首版使用的字体未覆盖中文，渲染后出现缺字方框；改用微软雅黑字体嵌入，重新渲染并逐页检查。
- 规格复核发现第3或第5段被设为必留时，缩短海景仍会缩短它；已修正为避开必留片段，保持“完整保留”的承诺。
- 对比初稿时，播放器切回初稿但片段卡仍显示修改后的时间；已同步时间轴与播放高亮，避免显示和实际跳转错位。
- 播放器异步加载与播放切换存在竞态；制作过程中调整取消、切换和加载状态，避免过期操作影响当前播放。
- 说明文档原写“确认30秒目标时长”，但实际没有时长设置控件；改为完整示例30秒、自定义随选片变化，并明确MP4/WebM导出规则、实时等待和标题未烧录的限制。

## 可复核的媒体行为

- 必留片段：第4段“同行的这一刻”，长度6秒。
- 基础版：8段素材共30秒。
- 突出海浪声：在必留片段减弱配乐、突出后期加入的海浪实录，视频长度仍为30秒。
- 缩短海景：第3段“浪花靠近”和第5段“慢慢看海”各由4秒缩至1秒，总时长变为24秒，第4段仍为6秒。
- 组合修改：同时突出海浪声和缩短海景，总长24秒。版本与片段清单见assets/media/manifest.json。
